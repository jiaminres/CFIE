# 2026-05-26 GUI Agent 截图分辨率定位实验

## 目的

验证在 2560x1440 物理屏幕口径下，Qwen3.5-VL 对一个右下角发送按钮的坐标定位，需要多高的输入图分辨率才能稳定命中。

## 方法

- 生成一张 `2560x1440` 合成 GUI 图。
- 在右下角放置深色圆角按钮，文字为“发送”。
- 真实按钮中心：
  - 物理像素：`[2380, 1328]`
  - Qwen 归一化坐标：`[929.6875, 922.2222]`
- 将同一张图缩放为不同输入分辨率，要求模型只输出按钮中心的 `0..1000` 归一化坐标。
- 将模型输出映射回 2560x1440，计算物理像素误差。

## 产物

- benchmark 脚本：`benchmarks/run_gui_agent_resolution_probe.py`
- 合成图和结果目录：
  - `.bench_logs/20260526_resolution_probe/full_20260526_091820`
  - `.bench_logs/20260526_resolution_probe/repeat1_20260526_092054`
  - `.bench_logs/20260526_resolution_probe/repeat2_20260526_092138`

## 结果

| 输入分辨率 | 轮数 | 平均误差，折算 2K 物理像素 | 最大误差 | 平均输入 tokens | 平均响应耗时 |
|---:|---:|---:|---:|---:|---:|
| 384x216 | 1 | 10.32 px | 10.32 px | 180 | 6.85s |
| 512x288 | 3 | 7.10 px | 7.10 px | 240 | 4.43s |
| 640x360 | 1 | 6.18 px | 6.18 px | 316 | 3.88s |
| 768x432 | 3 | 13.44 px | 19.71 px | 432 | 5.64s |
| 960x540 | 3 | 5.81 px | 7.96 px | 606 | 4.87s |
| 1280x720 | 3 | 8.06 px | 8.30 px | 976 | 5.35s |
| 1600x900 | 3 | 5.63 px | 7.96 px | 1496 | 9.30s |
| 1920x1080 | 3 | 2.02 px | 2.49 px | 2136 | 6.26s |
| 2560x1440 | 3 | 3.94 px | 4.66 px | 3696 | 8.53s |

所有成功解析的档位都落在按钮框内。低分辨率也能命中这个较明显按钮，但输出格式不稳定；高分辨率主要提升的是小控件精确定位余量。

## 结论

- `960x540` 已经能命中明显按钮，但对真实全屏小控件偏紧。
- `1600x900` 是当前推荐默认值：误差进入个位数，且视觉 token 低于 `1920x1080`，更适合保持 GUI Agent 响应速度。
- `1920x1080` 精度最好，但视觉 token 约 `2136`，已经接近或超过常用 `max_num_batched_tokens=2096`，更适合关键定位重试或高精度模式。
- 继续保留 CLI/客户端配置项，允许不同 APP 在“低延迟模式”和“高精度模式”之间切换。
